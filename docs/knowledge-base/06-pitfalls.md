# 06. 자주 생기는 문제

대화를 읽다가 아래 증상이 보이면 지식 베이스에서 고칠 수 있는 원인부터 확인합니다. 모든 증상이 재료 때문은 아니며, 같은 표현을 되풀이하는 것처럼 모델의 생성 특성에서 오는 것도 있습니다. 또 예상과 다른 흐름이 모두 문제는 아닙니다. 사실이 틀렸거나 처지를 지어낸 경우가 아니라면 그것도 시뮬레이션 결과입니다. 괄호 안 수치는 한국어 교육정책 시뮬레이션(EXAONE·A.X)에서 실측한 값입니다. 모델에 따라 증상이 나타나는 정도는 다를 수 있지만, 원인을 찾는 순서는 같습니다.

| 증상 | 흔한 원인 | 대응 |
|---|---|---|
| 모두 같은 화제로 모인다 | 카드가 없거나 적음, 카드가 한쪽 틀에 몰림 | 카드 수를 시민 수 이상으로, 논거 유형·관점·찬반을 고르게 ([03](03-cards.md)) |
| 남의 말을 거의 그대로 옮긴다 | 카드 없는 시민이 많음, 카드에 원글 문장이 들어감 | 카드를 관심사 이름과 짧은 구절로 줄임. 원글 문장을 넣었을 때보다 따라 하기가 크게 줄었음 |
| 없는 사실을 단정한다 | 주제 정보에 사실이 적음, 시기·대상이 빠짐 | 사실을 8\~12개로, 시기·대상을 문장 안에 ([02](02-digest.md)) |
| 소문을 사실처럼 말하고 번진다 | 구체 사실이 카드의 관심사나 첫 메시지에 들어감 | 구체 사실은 `premises`로 옮기고 범위·시기를 적음. 첫 메시지에 지명·수치를 넣지 않음 (단정 하나가 한 회에 최대 18회 반복) |
| "그런 얘기는 없던데"처럼 정보가 없다는 말이 되풀이된다 | `not_stated`(원문에 없는 것)를 넣음 | `not_stated`를 비우고, 궁금한 점은 카드의 `ask_form`으로 |
| 소문·유출 정보를 확정된 것처럼 말한다 | 확인되지 않은 내용을 확정 상태로 주제 정보에 넣음 | 상태를 `유출·루머`처럼 구분하거나, 카드의 `premises`(들은 얘기)로 옮김 |
| 실제 제품·작품을 두고 모델이 원래 아는 정보를 섞는다 | 실제 이름을 썼는데 사실 목록이 빈약함 | 가격·사양·출연진 등 대화에 나올 사실을 목록에 빠짐없이 넣음 |
| 처지를 지어낸다 | 자녀·대상 여부 등 사실 칸이 비어 있음 | `kids`, `relation`, `stage`를 채움. "처지에서 말하라" 지시는 넣지 않음 (지시를 넣었을 때 지어냄 3배) |
| 자기소개로 말을 시작한다 ("60대로서") | 긴 서사, 3인칭 요약 | 서사 대신 사실 한 줄씩. 가끔 나오는 것은 자연스러운 범위 |
| 카드 문구나 칸 이름이 발언에 나온다 ("[관심사]에 적힌") | 칸 문구가 지시처럼 읽힘 | 카드 `interest`를 명사구로. 사양의 칸 이름은 그대로 두는 편이 안전 |
| 소식 얘기를 피한다 | `common_words`가 비어 주제 낱말이 반복 표현으로 안내됨 | `common_words`에 주제 낱말을 넣음 ([05](05-topic-and-spec.md)) |
| 모두 "취지는 좋지만 걱정된다"로 끝난다 | 입장 기울기를 지정하지 않음 | 근거가 있는 범위에서 `lean` 지정 ([04](04-personas.md)) |
| 셋째 날쯤 화제가 다시 모인다 | 카드가 일찍 소진됨 | 시민당 카드 2장(`cards_per_person: 2`), 하루 단위 대화 초기화 옵션 고려 |
| 틀린 상식을 말한다 (예: 어느 도시에 대학이 없다) | 모델이 원래 아는 지식 | 주제 정보로 막을 수 없음. 주제와 관계된 사실이면 사실 목록에 넣음 |
| 같은 설정인데 회차마다 결과가 다르다 | 모델 샘플링, 호출 완료 순서 | 3회 이상 돌려 평균으로 비교 (같은 설정의 점수가 40점 넘게 흔들린 사례) |

## 점검 순서

1. `examples` 폴더에서 `python -m kb_tools.validate <폴더>`로 형식과 구성 경고를 먼저 없앱니다.
2. `kb_tools.run`이 남긴 `out/<도메인>/prompts.json`에서 시민 두세 명의 system 프롬프트를 읽습니다. 카드와 사실이 의도대로 들어갔는지 확인합니다.
3. 20\~40메시지로 짧게 돌려 대화를 읽고, 위 표에서 증상을 찾습니다.
4. 지식 베이스를 고친 뒤 같은 길이로 다시 돌려 비교합니다.
