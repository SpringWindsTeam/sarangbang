# 03. 쟁점 카드 만들기

쟁점 카드는 사람들이 이 소식을 두고 **꺼낼 만한 관심사**를 한 장씩 정리한 것입니다. 시민 한 명이 보통 1~2장을 받고, 받은 카드는 `[관심사]`로, 카드가 없는 시민에게는 남는 카드 하나가 `[들은 얘기]`로 들어갑니다.

카드는 시민이 대화에서 꺼낼 수 있는 **관심사의 후보**이지 대사가 아닙니다. 시민은 카드를 자기 말로 바꿔 말하라는 안내를 받고, 대화 흐름에 따라 카드와 다른 얘기도 합니다. 카드가 하는 일은 시민마다 다른 출발점을 주는 것이고, 카드에 없는 관점이 대화에서 새로 나오는 것도 기대하는 결과입니다.

시민마다 다른 카드를 주는 것은 실제 사회의 모습을 반영한 설계입니다. 같은 소식을 들어도 사람마다 그 일에 대해 원래 알던 정도, 주변에서 새로 전해 들은 얘기, 마음에 걸리는 지점이 다르고, 그 차이가 반응의 차이로 이어집니다. 카드의 `[관심사]`는 그 사람이 먼저 신경 쓰는 지점을, `[들은 얘기]`는 출처가 붙은 전해 들은 얘기를 나타냅니다. 원래 알던 정도의 차이는 주제 정보를 보여 주는 범위(소식의 대상이 아닌 시민은 사실을 앞 4개만 봅니다)와 시민 정보가 나눠 맡습니다. 모든 시민에게 같은 정보를 주면 이런 차이가 사라집니다.

카드가 없을 때는 시민들이 같은 화제(대개 첫 메시지의 화제나 가장 뻔한 걱정)로 모인 경우가 많았습니다. EXAONE·A.X 실측에서 카드 없이 30명을 돌렸을 때 같은 화제 두세 개로 수렴했고, 남의 발언을 통째로 옮긴 경우가 3건 나왔습니다.

## 형식

`cards.json`은 카드 id를 키로 하는 객체입니다.

```json
{
  "c1": {
    "id": "c1",
    "name": "야간 안전",
    "interest": "밤늦게 차를 대고 걸어가는 길의 안전",
    "ask_form": "요금 받는 만큼 조명이나 CCTV는 늘리나?",
    "perspective": "인근 주민",
    "require": ["resident"],
    "arg_types": ["안전"],
    "freq": 4,
    "stance_lean": {"lean": "조건부"},
    "premises": [{"premise": "옆 동네는 유료화 뒤 주차장 조명을 바꿨다", "scope": "옆 동네 한 곳", "time": "작년"}],
    "sources": [{"kind": "시민 의견", "platform": "cafe"}]
  }
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `id` | 예 | 키와 같은 값 |
| `name` | 예 | 관심사 이름. 짧은 명사구(2~8자) |
| `interest` | 예 | 무엇이 궁금하거나 걱정되는지 한 구절. 원글 문장을 옮기지 않습니다 |
| `ask_form` | 권장 | 이 관심사를 가진 사람이 단톡방에 던질 법한 질문 한 문장 |
| `perspective` | 아니요 | 이 관심사가 주로 나오는 관점(이용자, 운영자, 학부모 등). 같은 관점의 시민에게 먼저 배분됩니다 |
| `require` | 아니요 | 이 카드를 받을 수 있는 시민 조건. 시민의 `situation` 태그가 모두 있어야 합니다 |
| `arg_types` | 예 | 논거 유형. 첫 번째 값으로 카드를 묶어 유형이 고르게 배분됩니다 |
| `freq` | 예 | 수집 자료에서 나온 횟수(1 이상). 배분 우선순위에만 쓰입니다 |
| `stance_lean.lean` | 예 | `찬성` / `반대` / `조건부` / `중립` |
| `premises` | 아니요 | 원글에 있던 구체적인 사실 주장. `scope`(범위), `time`(시기)을 함께 적습니다 |
| `sources` | 아니요 | 출처. 첫 번째 출처로 `[들은 얘기]`의 출처 표현이 정해집니다: `kind`가 `단체 성명`이면 "어느 단체 성명", `기사 옮김`이면 "옮겨진 기사", 그 밖에는 `platform`이 `blog`면 "블로그 글", 아니면 "온라인 카페 글" |

## 수집

| 소스 | 얻을 수 있는 것 | 주의 |
|---|---|---|
| 커뮤니티·카페 글과 댓글 | 생활 속 걱정, 구체적 경험 | 불만 글이 많이 올라옴. 긍정 후기는 따로 검색 |
| 블로그·리뷰 | 이용 경험, 비교 | 광고·협찬 글 제외 |
| 영상·기사 댓글, SNS | 빠른 첫 반응, 유행하는 말 | 짧고 거친 표현이 많음. 관심사만 뽑고 말투는 옮기지 않음 |
| 팬 커뮤니티 | 열성 이용자·팬의 관심사 | 한쪽 관점이 강함. 일반 이용자 자료와 함께 씀 |
| 민원·의견 게시판, 사내 게시판 | 요구 사항, 질문 | 같은 사람이 여러 번 쓰는 경우 |
| 단체 성명·보도자료 | 조직의 공식 입장 | 카드로 쓸 때 `sources[0].kind: "단체 성명"` |
| 기사 | 논점 정리 | 기자의 틀이 그대로 들어오므로 기사만으로 카드를 만들지 않음 |

수집할 때 정할 것:

- **찬반 균형**: "불편", "반대" 같은 말로만 검색하지 말고 "좋아졌다", "후기", "만족" 같은 말로도 검색합니다.
- **관점 균형**: 이 소식에 걸린 사람들의 유형을 먼저 적고(예: 주차장 이용 주민·인근 상인·차 없는 주민 / 기존 사용자·구매 예정자·경쟁 제품 사용자 / 원작 팬·일반 시청자), 유형마다 자료를 찾습니다.
- **원문 보관**: 수집 원문은 카드를 만든 뒤 일정 기간이 지나면 지웁니다. 카드에는 원문 문장을 남기지 않습니다.
- **이용 약관**: 수집하는 사이트의 약관과 저작권을 확인합니다.

## 카드 작성 규칙

1. **한 카드에 관심사 하나.** "요금도 비싸고 안전도 걱정"은 두 장으로 나눕니다.
2. **원글 문장을 옮기지 않습니다.** 원글 문장을 카드에 넣었을 때 시민이 그 문장을 거의 그대로 옮겨 말하는 경우가 많았고, 관심사 이름과 짧은 구절로 줄였을 때 그런 경우가 거의 없어졌습니다(EXAONE·A.X 실측).
3. **원글 전달·기사 요약은 카드가 아닙니다.** "이런 기사가 났다"는 내용은 카드로 만들지 않습니다.
4. **구체 사실은 `premises`로.** "옆 동네는 조명을 바꿨다" 같은 내용은 관심사가 아니라 전제입니다. 범위와 시기를 모르면 "범위 미상", "시기 미상"이라고 적습니다.
5. **관점이 다르면 다른 카드.** 같은 "요금" 얘기라도 이용 주민과 인근 상인은 관심사가 다릅니다.
6. **한 번만 나온 관심사도 남깁니다.** 의미가 거의 같은 카드는 나중에 한꺼번에 합칩니다.

## 몇 장이 필요한가

시민 수 × 시민당 카드 수(`meta.json`의 `cards_per_person`, 기본 1)보다 넉넉하게 만듭니다. 카드가 모자라면 뒤쪽 시민은 카드를 받지 못합니다. `require` 조건이 있는 카드는 맞는 시민에게만 갈 수 있으니, 조건 없는 카드도 충분히 둡니다.

`kb_tools.validate`는 다음을 점검합니다.

- 찬반 방향이 한쪽에 쏠렸는지(한 방향이 70% 이상이면 경고)
- 맞는 시민이 한 명도 없는 카드
- 카드 수가 시민 수보다 적은지
- `premises`에 범위·시기가 비었는지

## 관련성 판정

카드마다 이 소식과의 관련성을 세 가지로 판정합니다.

| 값 | 뜻 |
|---|---|
| `direct` | 이 소식을 두고 바로 나올 쟁점 |
| `related` | 대화하다 자연스럽게 넘어갈 수 있는 쟁점 |
| `unrelated` | 이번 대화와 관계없음. 배분하지 않음 |

`relevance.json`을 직접 쓰거나, 비워 두면 `kb_tools.run`이 실행 때 LLM(`sarangbang.material.relevance`)으로 판정합니다. 카드를 여러 소식에 재사용하는 경우(예: 동네 소식 카드 묶음) LLM 판정이 편합니다.

## LLM으로 만들기

```bash
cd examples
python -m kb_tools.make_cards 수집글.jsonl -o knowledge-bases/my-topic/cards.json --title "공영주차장 야간 유료화"
```

입력은 한 줄에 글 하나인 JSONL입니다.

```json
{"text": "퇴근이 늦어서 밤에만 차를 대는데 이제 돈 내야 하네요...", "platform": "cafe", "date": "2026-10-01"}
```

[`examples/kb_tools/make_cards.py`](../../examples/kb_tools/make_cards.py)는 글을 묶음으로 나눠 위 규칙을 지시하고, 결과를 이름 기준으로 합칩니다. 전제는 카드마다 "글에 나온 다른 곳 사례·직접 본 현상" 하나만 받고, '가능성', '~수 있다' 같은 추측 표현이 든 것은 코드로 거릅니다. 전제 칸을 목록으로 받으면 모델이 추측과 소식 내용까지 채워 넣었기 때문입니다. 만든 카드는 사람이 다음을 점검합니다.

- [ ] 원글 문장이 그대로 들어간 카드가 없는가
- [ ] 소식을 전달하기만 한 글(링크 공유, "언제부터래요")에서 나온 카드가 없는가
- [ ] 찬성·반대·조건부·중립이 모두 있는가
- [ ] 관점별 카드가 있는가
- [ ] premises의 범위·시기가 원글과 맞는가
