# 04. 시민 구성하기

시민은 대화에 참여하는 가상 인물입니다. 시민 정보는 그 사람이 **어떤 처지에서 말하는지**의 근거가 됩니다. 처지 정보가 비면 처지를 지어내는 경우가 있습니다. EXAONE·A.X 실측에서 자녀가 없는 30세가 "우리 아이 학교"를, 농업인이 "교사인 입장"을 말한 사례가 있었습니다.

## 형식 (DictAdapter)

[예시 지식 베이스](../../examples/knowledge-bases)는 sarangbang의 `DictAdapter` 필드를 씁니다. 모든 필드가 선택이지만, 아래 표의 "권장" 필드는 채우는 편이 좋습니다.

| 필드 | 프롬프트에서 | 설명 |
|---|---|---|
| `name` | 방 안 표시 이름 | 겹치지 않게. 예시에서는 동네 이름 |
| `me` | `[나]` | 나이대, 직업, 사는 곳 등 한 줄 (권장) |
| `kids` | `[우리 아이]` | 자녀와 학년. 없으면 비워 둡니다 |
| `personality` | `[내 성격]` | 성격 한 줄 |
| `values` | `[내 가치관]` | 가치관 한 줄 |
| `stage` | `[내 처지]` | 가족 형태, 생활 단계 (권장) |
| `relation` | 소식과의 관계 칸 | 이 소식이 나와 어떻게 닿는지 한 줄 (권장) |
| `living` | `[살림·동네]` | 집, 동네, 살림 형편 |
| `short_self` | 마무리 앞 자기 요약 | "40대 직장인 · 맞벌이"처럼 짧게 |
| `student_level` | 학생 규칙 | "고2"처럼 쓰면 학생 입장 규칙이 붙습니다 |
| `situation` | (보이지 않음) | 상황 태그 목록. 카드의 `require`와 맞물립니다 |
| `perspectives` | (보이지 않음) | 관점 목록. 같은 `perspective`의 카드를 먼저 받습니다 |
| `affected` | (보이지 않음) | 소식의 대상인지. `false`면 사실을 앞 4개만 봅니다. 기본 `true` |
| `score` | (보이지 않음) | 소식과 가까운 정도. 아래 참고 |
| `lean` | 입장 문장 | 입장 기울기 -1~1. 아래 참고 |
| `steady` | (보이지 않음) | `true`면 가벼운 찬성 말투를 붙이지 않습니다 |

## 도메인 속성은 어디에 넣나

`DictAdapter`의 칸 이름은 고정이지만, 내용은 도메인에 맞게 채웁니다. `kids`처럼 도메인과 관계없는 칸은 비워 둡니다.

| 넣을 정보 | 칸 | 신제품 출시 예 | 미디어 예 |
|---|---|---|---|
| 나이대·직업·사는 곳 | `me` | 30대 회사원, 지방 거주 | 20대 대학생 |
| 소식과 직접 닿는 사실 | `relation` | 지금 쓰는 폰이 3년 된 이전 모델이다 | 원작 웹툰을 연재 때부터 봤다 |
| 형편·생활 환경 | `living` | 할부가 끝나 기기 바꿀 때가 됐다 | OTT 두 개를 구독한다 |
| 생각하는 기준 | `values` | 비싸도 오래 쓰는 걸 산다 | 원작과 다르게 바꾸는 걸 싫어한다 |
| 가족 형태·생활 단계 | `stage` | 신혼 · 맞벌이 | 부모님과 산다 |
| 카드 조건용 표시 | `situation` | `current_user`, `rival_user` | `original_fan`, `casual_viewer` |

`relation`에는 "이 소식에 관심이 많다" 같은 태도보다, 태도를 낳는 **사실**을 적습니다. 태도는 `lean`(입장 기울기)이 따로 맡습니다.

## 상황 태그와 카드 조건

`situation`은 시민이 어떤 조건에 해당하는지 나타내는 태그 목록이고, 카드의 `require`는 그 카드를 받을 수 있는 조건입니다. 카드의 `require`에 있는 태그를 시민이 모두 가지고 있어야 카드가 배분됩니다.

```json
// 시민
{"name": "망원", "situation": ["resident", "car_owner"], ...}
// 카드: 차가 있는 주민만
{"id": "c3", "require": ["car_owner"], ...}
```

태그 이름은 도메인마다 자유롭게 정하되, 한 지식 베이스 안에서는 같은 이름을 씁니다. `kb_tools.validate`는 카드의 `require`에 있지만 어느 시민에게도 없는 태그를 경고합니다.

## 점수(score)와 입장 기울기(lean)

**score**: 소식과 가까운 정도입니다. 세 곳에 쓰입니다.

- 점수가 가장 높은 시민이 첫 메시지를 올립니다.
- 점수가 높을수록 발언 순위가 앞섭니다.
- 앵커 레인을 쓸 때 점수 상위 1/6이 앵커 모델로 말합니다.

대상 당사자 3, 가족이나 이웃이 당사자 2, 간접 관계 1, 무관 0 정도로 매기면 충분합니다.

**lean**: -1(강한 반대) ~ 1(강한 찬성), `null`이면 입장 문장을 넣지 않습니다. 절댓값 0.6 이상은 강, 0.3 이상은 중, 0.05 이상은 약으로 바뀌어 "당신은 이 일을 대체로 좋게 보는 사람이다" 같은 문장이 됩니다.

입장을 지정하지 않으면 시민 대부분이 "취지는 좋지만 걱정된다"는 조건부 의견으로 모이는 경향이 있었습니다(EXAONE·A.X). 입장 분포를 정할 근거(여론조사, 설문, 성향 데이터)가 있으면 그것을 따르고, 없으면 일부 시민만 지정하고 나머지는 `null`로 둡니다. 근거 없이 무작위로 배정하지 않습니다.

## 방 크기

방 하나에 30~40명을 권장합니다. 그보다 많으면 방을 여러 개로 나누고, 시민을 입장·처지·나이가 섞이도록 번갈아 배정합니다. 예시 지식 베이스는 설명용이라 6~8명입니다.

## 공개 데이터셋 쓰기

인구 분포를 따르는 시민이 필요하면 [Nemotron-Personas-Korea 증강판](https://huggingface.co/datasets/springwindteam/nemotron-personas-korea-augmented)(한국인 100만 명, 19세 이상, CC BY 4.0)과 sarangbang의 `NemotronKoreaAdapter`를 씁니다. 이 경우 `relation`과 `score`는 `target["relations"]` 규칙으로 정합니다.

```python
from sarangbang.adapters import NemotronKoreaAdapter

ad = NemotronKoreaAdapter()
target = {"relations": [
    {"if": {"housing_type": ["다세대주택", "연립주택"]}, "text": "주차 공간이 부족한 집에 산다", "score": 2},
    {"if": {"has_children": True}, "text": "아이들을 태우고 다닐 일이 많다", "score": 1},
]}
```

이 데이터셋에는 성격, 자녀 나이, 쓰는 제품, 콘텐츠 소비 습관이 없습니다. 이런 정보가 중요한 주제(학년별 정책, 특정 기기 사용자 대상 제품, 팬층이 갈리는 콘텐츠)라면 다른 데이터를 붙이거나 자기 어댑터를 만듭니다. 데이터에 없는 속성을 LLM으로 지어 붙이지 않습니다.

## 자기 어댑터 만들기

시민 데이터 형식이 다르면 sarangbang의 `PersonaAdapter` 프로토콜을 구현합니다. 메서드는 레코드를 받아 문장이나 값을 돌려줍니다.

| 메서드 | 돌려주는 것 |
|---|---|
| `fact_sections(p, target)` | 사실 칸 문자열 목록(`[나] ...`, `[우리 아이] ...`) |
| `stage_line(p)`, `relation_line(p, target)`, `living_line(p)`, `short_self(p)` | 각 칸의 한 줄 |
| `student_level(p)` | 학생이면 학년, 아니면 빈 문자열 |
| `affected(p, target)` | 소식의 대상인지 |
| `card_fits(card, p)` | 이 카드를 받을 수 있는지 |
| `own_perspectives(p)` | 관점 목록 |
| `static_score(p, target)` | 점수 |
| `light_support_ok(p)` | 가벼운 찬성 말투를 붙여도 되는지 |
| `seed_profile(p, target)` | 첫 메시지를 쓸 때 줄 사실 목록 |
| `display_names(personas)` | 표시 이름 목록 |

## 넣지 않는 편이 나은 것

EXAONE·A.X 실측에서 효과가 없거나 해로웠던 것입니다. 다른 모델에서는 결과가 다를 수 있습니다.

- **긴 개인 서사 전체**: 발언이 나아지지 않고, 자기소개("울산 사는 37세 주부로서") 반복이 늘었습니다.
- **기억 원문 여러 편**: 한 사람의 경험을 다른 시민이 자기 경험처럼 말했습니다. 넣는다면 소식과 관련된 기억 한 편만 넣습니다.
- **말투 예시 문장**: 예시 문장이 발언에 그대로 반복됐습니다.
