# 01. 지식 베이스 구성 방법

## 무엇을 만드는가

이 문서들에서 **시민**은 대화에 참여하는 가상 인물을 말합니다(sarangbang의 용어). 도메인에 따라 소비자, 시청자, 직원, 주민이 됩니다. **소식**은 대화의 주제가 되는 일(정책, 신제품 출시, 방송·기사, 회사 공지, 가격 변경 등)입니다.

sarangbang의 시민은 매번 독립된 LLM 호출로 말합니다. 호출마다 들어가는 것은 두 메시지뿐입니다.

- **system**: 그 시민의 사실 정보, 이 소식에 대해 아는 것, 관심사, 전해 들은 얘기, 규칙
- **user**: 단톡방 화면 그대로의 대화 기록과 마무리 지시

시민에게는 기억이 없습니다. 시민이 이 소식에 대해 아는 것은 지식 베이스로 넣어 준 것, 대화 기록에 나온 것, 그리고 모델이 원래 아는 일반 지식입니다.

### 재료와 모델이 각각 하는 일

지식 베이스는 대화의 **출발점과 사실의 경계**를 정합니다. 대화 자체는 모델이 만듭니다.

| | 지식 베이스(재료) | 모델 |
|---|---|---|
| 하는 일 | 시민이 사실로 아는 범위, 처음 꺼낼 만한 관심사, 시민의 처지 | 다른 시민의 말에 공감·반박·농담으로 반응하기, 사실들을 엮어 해석하기, 대안 내놓기, 카드에 없는 관점 꺼내기 |
| 예 (실행 결과) | 카드 "정기권 공정성"(질문 예: "선착순이면 온라인 못 하는 어르신은 어떡하나?") | "차라리 주소지 기준으로 신청 받았으면 어땠을까", "늦게 퇴근하는 사람 전용 패스를 따로 만들었으면" (동네 소식, A.X) |
| | 사실 "다음 회 예고편에 최종 선택 전날 상철이 혼자 숙소 밖에 앉아 있는 장면이 나왔다" | "직진만 하다가 처음으로 멈칫한 느낌" (연애 예능, A.X) |

카드에 없는 관점이 대화에서 새로 나오는 것도 이 시뮬레이션에서 보려는 결과의 일부입니다. 그래서 재료는 대화가 사실에서 벗어나지 않고 시민마다 다른 출발점을 갖게 하는 데까지만 채웁니다. 재료를 대사처럼 촘촘하게 채우면 모델이 할 몫이 줄어듭니다(원칙 7).

| 구성 요소 | 시민에게 어떻게 보이나 | 비어 있을 때 관찰된 문제 (EXAONE·A.X) |
|---|---|---|
| 주제 정보 | `[알고 있는 것]`에 사실 목록으로 | 사실을 지어내거나 "모르겠다"만 반복한 경우 |
| 쟁점 카드 | `[관심사]`(자기 관심사와 던질 질문), `[들은 얘기]`(출처가 붙은 소문) | 같은 화제로 모이고 남의 말을 옮긴 경우 |
| 대상 | 시민과 소식의 관계 문장, 발언 순위 점수 | 소식과 무관한 사람이 당사자처럼 말한 경우 |
| 시민 | `[나]`, `[우리 아이]`, `[내 처지]`, `[내 성격]` 등 | 처지를 지어낸 경우(자녀 없는 사람이 "우리 아이 학교") |
| 주제 문구·사양 | 머리표, 입장 문장, 규칙, 마무리 지시 | 기본값(범용 문구) 사용 |

## 도메인별로 무엇을 넣나

구성 요소는 어느 도메인이든 같고, 채우는 내용만 달라집니다.

| | 정책·공공 | 신제품 출시 | 미디어(방송·기사·콘텐츠) | 회사 공지 |
|---|---|---|---|---|
| 주제 정보 원문 | 보도자료, 공고문 | 출시 발표, 제품 페이지, 가격표 | 공식 발표, 보도 기사, 제작사 공지 | 사내 공지 |
| 상태 어휘 예 | 확정·시행 / 계획·목표 / 과거 실적 / 검토 | 공식 발표 / 출시 예정 / 유출·루머 / 이전 모델 | 공식 확인 / 보도 / 루머 / 지난 시즌 | 확정 / 예정 / 검토 / 지난 사례 |
| 쟁점 카드 출처 | 커뮤니티, 민원, 단체 성명 | 리뷰, 커뮤니티, 사전 반응 글, 유튜브 댓글 | 시청 후기, 팬 커뮤니티, SNS, 기사 댓글 | 사내 게시판, 설문 응답 |
| 관점 예 | 학부모, 주민, 교직원 | 기존 사용자, 구매 예정자, 경쟁 제품 사용자 | 원작 팬, 일반 시청자, 출연자 팬 | 대상 부서, 제외 부서 |
| 시민 속성 예 | 자녀 학년, 거주지, 직업 | 쓰는 기기·서비스, 구매 주기, 예산 | 시청 습관, 팬 여부, 쓰는 플랫폼 | 부서, 직군, 근무 형태 |
| 대상(target) | 정책 적용 대상 | 출시 지역·대상 고객 | 시청자·독자층 | 적용 부서 |

상태 어휘는 `meta.json`의 `statuses`로 정합니다([02](02-digest.md)). 시민 속성을 어느 칸에 넣는지는 [04](04-personas.md)에 있습니다.

## 원칙

아래 원칙의 수치는 한국어 교육정책 시뮬레이션에서 EXAONE·A.X 모델로 실측한 결과입니다. 다른 도메인과 다른 모델에서는 아직 측정하지 않았고, 모델에 따라 정도가 다를 수 있습니다(예: 긴 입력을 더 잘 다루는 모델도 있습니다). 그래도 원칙 자체는 특정 모델의 약점을 피하는 요령이라기보다 입력을 깔끔하게 나누는 방법이라, 어떤 모델이든 출발점으로 쓰기를 권합니다. 모델을 바꾸면 [06](06-pitfalls.md)의 점검 순서대로 대화를 다시 읽어 봅니다.

### 1. 사실과 의견을 나눈다

확인된 사실은 주제 정보에, 사람들의 관심사·주장·소문은 쟁점 카드에 둡니다. 둘을 섞었을 때 시민이 소문을 사실처럼 단정하고, 그 단정이 대화 안에서 번진 경우가 있었습니다. 실측에서는 한 회 대화 안에서 단정 하나가 최대 18번 반복됐습니다.

카드에 들어 있는 구체적인 사실(예: "다른 나라는 하교 시간이 2시 30분")은 `premises`에 출처·범위·시기와 함께 적습니다. sarangbang은 이를 `[들은 얘기]`로 보여 주고, 추측·의문형으로만 말하게 합니다.

### 2. 재료는 짧은 칸으로 넣는다

문서 원문, 검색 결과, 긴 서사를 통째로 넣지 않습니다. EXAONE 실측에서 웹검색 결과 2,500자를 넣었을 때 출력 형식이 무너졌고, 700자로 줄여도 출력이 잘렸습니다. 개인 서사 전체를 넣었을 때도 발언이 나아지지 않고 자기소개 반복만 늘었습니다.

사실은 한 줄씩, 관심사는 명사구로, 질문은 한 문장으로 줄여서 넣습니다.

### 3. 지시보다 재료를 준다

"당신의 처지에서 말하라" 같은 지시는 기대만큼 듣지 않을 수 있습니다. 실측에서 이 지시를 넣었을 때 지어낸 처지가 3배로 늘었습니다. 반대로 "자녀: 초2, 이 소식의 대상에 해당함" 같은 사실 칸을 넣었을 때 처지를 맞게 말하는 비율이 13%에서 57~79%로 올랐습니다.

무엇을 말하게 하고 싶으면, 지시를 쓰기 전에 그 내용을 사실이나 관심사 칸으로 줄 수 있는지 먼저 봅니다.

### 4. 시민마다 다른 출발점을 준다

한쪽으로 치우친 재료를 넣으면 대화도 그쪽으로 기울 수 있습니다. 실측에서 한쪽 주장이 강하게 담긴 기사를 시드로 넣었더니 그 표현이 발언의 69~81%에 나왔고, 시드를 빼자 0~4%로 떨어졌습니다.

실제로도 같은 사건을 두고 사람마다 알고 있는 것과 들은 얘기, 관심 두는 지점이 달라 반응이 갈립니다. 시민마다 다른 카드를 주는 것은 이 차이를 재료로 옮긴 것입니다([03](03-cards.md)). 출발점이 다양하면 그 사이에서 모델이 새 관점을 만들어 낼 여지도 커집니다. 카드를 만들 때 찬성·반대·조건부·중립, 논거 유형(비용·안전·편의·공정 등), 관점(이용자·운영자·인근 주민 등)이 고르게 들어가도록 합니다. 긍정적인 목소리는 수집 단계에서 일부러 찾아야 합니다. 불만 글이 더 많이 올라오기 때문입니다.

### 5. 카드 빈도는 여론 비율이 아니다

카드의 `freq`는 같은 관심사가 수집 자료에서 몇 번 나왔는지입니다. 쟁점을 빠짐없이 확보하는 데 쓰고, "이 의견이 몇 %"라는 근거로 쓰지 않습니다. 한 번만 나온 관심사도 카드로 남깁니다.

### 6. 시민은 실제 분포를 따르는 데이터에서 가져온다

시민 정보를 LLM으로 지어내거나 무작위로 섞지 않습니다. 인구 분포를 따르는 데이터셋(예: [Nemotron-Personas-Korea 증강판](https://huggingface.co/datasets/springwindteam/nemotron-personas-korea-augmented))에서 조건에 맞게 뽑고, 데이터에 없는 정보는 비워 둡니다.

### 7. 재료를 대사처럼 채우지 않는다

재료는 시민이 무엇을 알고 무엇에 관심을 두는지까지만 줍니다. 무엇을 어떻게 말할지까지 정해 주려 하지 않습니다.

- 카드에는 관심사 이름과 짧은 구절만 넣고, 시민이 할 말을 문장으로 써 두지 않습니다. `ask_form`은 질문의 한 예이지 그대로 말할 대사가 아닙니다.
- 시민마다 모든 쟁점을 다 쥐여 주지 않습니다. 시민당 카드 1~2장이면 나머지는 대화 속에서 다른 시민에게 듣고 반응합니다.
- 대화에서 기대한 말이 안 나왔다고 바로 재료를 늘리지 않습니다. 사실이 틀렸거나 처지를 지어낸 경우가 아니라면, 예상과 다른 흐름도 결과로 봅니다.

## 작업 순서

| 단계 | 할 일 | 문서·도구 |
|---|---|---|
| 1 | 소식 하나를 정하고, 누가 대상인지(`target`) 적는다 | 이 문서 |
| 2 | 원문에서 주제 정보를 뽑고 사람이 검수한다 | [02](02-digest.md), `kb_tools.extract_digest` |
| 3 | 사람들의 글·댓글을 모아 쟁점 카드를 만들고 검수한다 | [03](03-cards.md), `kb_tools.make_cards` |
| 4 | 시민을 뽑고, 카드 조건과 맞물리는 상황 태그를 붙인다 | [04](04-personas.md) |
| 5 | 주제 문구와 사양을 고른다 | [05](05-topic-and-spec.md) |
| 6 | 형식과 구성을 점검한다 | `kb_tools.validate` |
| 7 | 모델 없이 → 짧게(20~40메시지) → 본 실행 순으로 돌리며 프롬프트 파일과 대화를 읽는다 | `kb_tools.run`, [06](06-pitfalls.md) |
| 8 | 같은 기준으로 3회 이상 돌려 비교한다 | 아래 |

### 결과를 비교할 때

같은 지식 베이스라도 모델 샘플링과 호출 완료 순서 때문에 회차마다 결과가 다릅니다. 실측에서는 같은 설정의 품질 점수가 회차 사이에 40점 넘게 흔들린 적이 있습니다. 지식 베이스나 사양을 고친 효과를 볼 때는 **같은 기준으로 3회 이상 돌린 평균**을 비교합니다.

메시지마다 세어 볼 만한 항목은 다음과 같습니다.

- 주제 정보에 없는 사실을 단정함
- 전해 들은 얘기를 이번 소식의 사실처럼 말함
- 프롬프트 칸 이름이 발언에 노출됨(예: "[관심사]에 적힌 대로")
- 남의 발언을 거의 그대로 옮김
- 처지를 지어냄
- 대화에 나온 서로 다른 화제의 수
